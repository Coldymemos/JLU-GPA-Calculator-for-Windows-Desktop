# JLU GPA 计算器 · 本地化（WebUI）功能规划

> 版本：v0.1（规划稿）　|　关联分支：`Coldymemos-adaption`　|　项目根：`WebEdition/`
>
> 范围：仅覆盖「文件系统访问」「更强的解析与计算」「数据规模与存储自由」三个方向。
> GPA 走势、多年档案分析等**网页端也能做**的功能，不作为本地化差异点展开，但在「数据规模」一节预留其数据基础。

---

## 0. 背景与设计约束

当前项目为浏览器本地优先 PWA：成绩只在浏览器中解析，课程与设置存于 IndexedDB。本地化（WebUI，推荐 Tauri 形态）的核心增量是**越过浏览器沙箱**。

两条必须遵守的设计约束：

1. **文件名不可靠原则**
   用户放入的目录中，文件名没有规律的命名习惯（可能是 `成绩(1).xls`、`2024秋-张三-全部课程.xlsx`、`新建文档.csv`、纯数字/乱码名等）。因此：
   - **一切识别以内容为准**：扩展名只作为候选筛子，实际格式与表头类型通过解析文件内容判断；
   - 文件名仅用于展示、去重提示与冲突命名，绝不作为解析依据；
   - 系统不得假设"一个文件 = 一个学期/一个学生"，归档关系由内容元数据（学期、课程号、成绩列）推导，无法推导时交给用户确认。
2. **兼容现有能力**
   本地化不破坏现有网页端：导入/导出的数据格式互通（JSON 配置、适配表格、xlsx），规则集与课程数据可无损迁移。

## 1. 总览：本地化形态

| 方案                    | 说明                                                               | 推荐度 |
| ----------------------- | ------------------------------------------------------------------ | ------ |
| **Tauri 2（推荐）**     | 复用现有 React UI，Rust 后端提供文件/存储/系统能力；安装包 ~10MB   | ★★★    |
| Electron                | 全 JS 栈、上手最快，但体积大（~150MB+）、内存占用高                | ★★     |
| 本地 Node 服务 + 浏览器 | 最快落地 WebUI，但无原生托盘/通知/安全存储，多端暴露端口有安全成本 | ★      |

文档内技术要求默认按 **Tauri 2（Rust 后端 + 前端复用现有 src/）** 编写，关键点标注 Electron 等价方案。

## 2. 文件系统访问

### 2.1 功能规划

**P0（首期必做）**

| 功能               | 说明                                                                                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目录选择与记忆     | 用户选择一个（或多个）导入目录；路径持久化到本地配置，重启后恢复                                                                                                        |
| 批量扫描导入       | 扫描目录（含子目录，深度可配）内候选文件，加入导入队列；**不依赖文件名**，仅按扩展名过滤候选                                                                            |
| 内容嗅探识别       | 读取文件内容判断：格式（xls/xlsx/csv/后续 pdf/html）、表头类型（复用现有 jlu-sheet / generic-sheet 探测，扩充教务多风格表头）；文件名与识别结果不一致时以内容为准并提示 |
| 导入队列与失败隔离 | 串行处理队列；单个文件解析失败不中断其余文件；产出逐文件报告（成功 / 跳过 / 失败 + 原因 + 可重试）                                                                      |
| 内容级去重         | 文件内容 sha256 指纹，重复文件自动跳过；课程级沿用现有「同一课程号保留最高有效成绩」规则                                                                                |
| 手动选择器保留     | 保留现有文件选择器入口（兼容未授权的目录、单文件快速导入）                                                                                                              |

**P1（次期）**

| 功能              | 说明                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------- |
| 目录监听（watch） | 监听目录新增/修改/删除事件，新文件自动进队；可在设置中开关                             |
| 一键备份          | 将全部数据（课程、规则、设置）备份为单个文件到指定目录，文件名含时间戳；支持恢复前校验 |
| 定时自动备份      | 间隔可配置（每日/每周）；备份文件保留份数上限                                          |
| 导出直写路径      | PNG/PDF/xlsx 结果导出时默认写入指定目录，可记忆上次路径                                |
| 冲突处理          | 同名文件、同内容不同名的处理策略（跳过 / 覆盖 / 追加），统一在导入报告界面确认         |

**P2（远期）**

| 功能         | 说明                                                                |
| ------------ | ------------------------------------------------------------------- |
| 拖拽文件夹   | 支持整文件夹拖入（Tauri 拖放事件），自动授权该目录                  |
| 多目录聚合   | 多个来源目录聚合为"资料库"，按内容元数据归并                        |
| 导入规则模板 | 把用户对某类文件的表头映射/清洗规则保存为模板，下次同类文件自动套用 |

### 2.2 技术要求

| 项       | 要求                                                                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目录能力 | Tauri：`tauri-plugin-dialog`（选目录）+ capabilities 配置最小授权（读/写分离，写仅限用户显式授权的目录）；Electron：`dialog` + `fs`                                  |
| 文件监听 | Rust `notify` crate（Tauri）；Electron 用 `chokidar`；需处理防抖（300–500ms）避免批量事件风暴                                                                        |
| 内容指纹 | `sha256` 全文指纹；大文件（>10MB）可只对头部 1MB + 文件大小做近似指纹（可配置）                                                                                      |
| 解析通道 | 复用现有 `parseSpreadsheetFile`（SheetJS 在 Node/Rust 侧均可运行）；Rust 侧解析用 `calamine`（xlsx/xls 原生解析，速度更快）或直接复用前端 js 解析逻辑跑在 WebView 内 |
| 队列模型 | 前端维护任务队列（现有 ImportPreview 模型扩展），Rust 只做文件 IO；解析失败返回结构化错误（文件级/行级分开）                                                         |
| 大文件   | >50MB 文件：异步解析 + 进度事件；限制单文件大小上限（默认 200MB，可配）                                                                                              |
| 路径安全 | 所有路径校验防穿越（`..`）、禁止跟随符号链接逃逸授权目录                                                                                                             |

## 3. 更强的解析与计算

### 3.1 功能规划

**P0**

| 功能           | 说明                                                                                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表头智能映射   | 现有手工 headerMapping 升级为「自动匹配 + 用户确认」：内置同义词库（课程号/课程代码/编号、成绩/总成绩/期末成绩/最终成绩、学分/绩点学分……），命中率低时进入映射确认界面 |
| 脏数据清洗规则 | 正则/规则管道：全角转半角、去括号批注（`90(重修)`→90）、`90.0分`→90、多余空白、空值策略（缺学分/缺成绩按现有 invalid-record 处理）                                     |
| 规则集并行模拟 | 同一份数据同时按多套规则集（不同年份/学院/专业）计算，结果并列展示对比——本地文件系统支撑的多档案让该功能有实际意义                                                     |

**P1**

| 功能            | 说明                                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| PDF 成绩单解析  | 本地解析 PDF（打印件/截图转 PDF）：提取表格区域 → 列聚类 → 复用表头映射与清洗管道；解析失败引导手动导入同源 xlsx/csv                   |
| HTML/文本成绩单 | 教务系统页面另存的 HTML、TXT 导出解析（规则化提取）                                                                                    |
| 反推与敏感度    | 输入目标 GPA → 反推还需提高哪些课、各涨多少分可达标；"去掉某门课 GPA 变化多少"敏感度分析（复用现有 CourseEvaluation 结果集，增量计算） |

**P2**

| 功能          | 说明                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| OCR（扫描件） | 扫描版成绩单 OCR：本地模型（Tesseract 中文 / PaddleOCR），识别后进入同一清洗管道；模型随包分发或按需下载 |
| 批量核算      | 多档案（多学生/多年度）一键批量核算并导出对比报表                                                        |
| 规则模板市场  | 用户分享规则集（沿用现有规则集 JSON 导出格式），导入即用                                                 |

### 3.2 技术要求

| 项         | 要求                                                                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PDF 解析   | 前端 `pdfjs-dist`（WebView 内渲染/提取）；Rust 侧 `lopdf`/`pdf-extract`；表格提取建议自研「坐标聚类 + 表头行定位」，通用 PDF 表格库对教务表格效果不稳定 |
| 同义词库   | 配置化 JSON（随应用分发，可被用户覆盖）；匹配算法用归一化字符串 + 编辑距离（现有 `normalizeText`/`normalizeCourseCode` 基础上扩展）                     |
| 清洗管道   | 规则声明式（JSON 数组：pattern + action），与现有 `course.normalizer.ts` 对齐，保证网页端同一套清洗结果一致                                             |
| 规则集并存 | 现有 `rule-set.types.ts` 已支持多 ruleSet 存 IndexedDB；本地化后改为 SQLite 存储，计算引擎保持纯函数（便于单测与并行）                                  |
| OCR        | Tesseract（`tesseract-rs`/`leptess`）中文模型 ~15MB；PaddleOCR 效果更好但模型更大（>100MB）；默认不内置，按需下载到本地缓存目录                         |
| 异步任务   | 解析/OCR 放 Rust 异步任务（`tauri::async_runtime` + tokio），进度通过事件通道回传；渲染层不得阻塞                                                       |

## 4. 数据规模与存储自由

### 4.1 功能规划

**P0**

| 功能          | 说明                                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 存储后端迁移  | IndexedDB → 本地 SQLite（主存储）；数据模型扩展为「档案 → 学期 → 课程」层级                                              |
| 一键迁移向导  | 从浏览器 IndexedDB 导出 JSON（全量数据，非仅过滤配置）→ 本地导入；逆向也支持（本地导出 JSON 给网页端导入），保证双端互通 |
| 多档案管理    | 支持多份成绩档案（多年/多学生/备份副本），切换查看；课程、规则、排除配置随档案独立                                       |
| 全量导出/恢复 | 导出为单个备份文件（SQLite 文件或 ZIP 包），含 schema 版本与校验和；恢复前校验版本兼容                                   |

**P1**

| 功能           | 说明                                                                    |
| -------------- | ----------------------------------------------------------------------- |
| 历史版本快照   | 每次导入/批量操作前自动快照，可回滚（轻量：增量 diff 或仅存操作前备份） |
| 大数据量性能   | 万级课程记录下：查询 < 100ms（带索引），计算保持现有 O(n) 实时渲染      |
| 开放格式互操作 | 课程/结果可导出 CSV、JSON、Excel，数据不锁定在私有库                    |

**P2**

| 功能              | 说明                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------ |
| 加密存储          | SQLite 加密（SQLCipher），密码保护，密钥存系统钥匙串（Windows Credential Manager / macOS Keychain）          |
| 年度/趋势数据底座 | 基于多档案与快照，沉淀「课程成绩历史」表，为网页端也能做的 GPA 走势提供本地大数据基础（本规划不展开走势 UI） |

### 4.2 技术要求

| 项              | 要求                                                                                                                                                                                                                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SQLite 接入     | Tauri：`rusqlite`（同步，适合本机单用户）或 `tauri-plugin-sql`（封装）；Electron：`better-sqlite3`；纯前端兜底 `sql.js`（WASM）                                                                                                                                                                                      |
| Schema 版本管理 | 从 0 开始设计 `schema_version` 表；迁移脚本按版本递增，启动时自动迁移；现有 IndexedDB schema（courses/ruleSets/settings）映射到 v2 表结构                                                                                                                                                                            |
| 表结构（草案）  | `archives(id, name, created_at)`；`courses(archive_id, id, code, name, term, grade_kind, grade_raw, credit, ...)` 索引 `(archive_id, code)`、`(archive_id, term)`；`rule_sets(archive_id, id, payload_json)`；`settings(archive_id, key, value_json)`；`course_history(archive_id, course_code, term, score)` 供趋势 |
| 备份格式        | 单文件 SQLite（`.db`）或 ZIP（db + manifest.json + 校验和）；恢复时校验 `schema_version` 与 `checksum`，失败则拒绝恢复并保留原数据                                                                                                                                                                                   |
| 加密            | SQLCipher（SQLite 加密扩展）或 SQLite 3 `SQLITE_CIPHER`；密钥不进明文配置文件，用系统凭据服务                                                                                                                                                                                                                        |
| 数据量基准      | 目标：10 万课程记录、100 份档案下全流程可用；导入 1 万行 xlsx < 3s（不含 UI）                                                                                                                                                                                                                                        |

## 5. 优先级与里程碑

| 里程碑           | 内容                                                              | 预计依赖 |
| ---------------- | ----------------------------------------------------------------- | -------- |
| M1：本地壳       | Tauri 骨架 + 现有 UI 可运行 + 目录授权 + 单文件导入走本地文件系统 | 无       |
| M2：存储迁移     | SQLite + 数据模型 v2 + 浏览器 JSON 迁移向导 + 全量备份/恢复       | M1       |
| M3：批量导入     | 目录扫描 + 内容嗅探 + 导入队列 + 内容级去重 + 失败报告            | M1、M2   |
| M4：解析增强     | 表头智能映射 + 清洗管道 + 规则集并行模拟                          | M2       |
| M5：文件系统进阶 | 目录监听 + 定时备份 + 导出直写 + 冲突处理                         | M3       |
| M6：解析进阶     | PDF 解析 + 反推/敏感度；OCR 视反馈再排                            | M4       |

> 建议顺序：M1 → M2 → M3 → M4，其中 M2（存储迁移）是后续所有能力的地基，应尽早定稿 schema。

## 6. 风险与兼容性

| 风险                     | 应对                                                                             |
| ------------------------ | -------------------------------------------------------------------------------- |
| 浏览器端仍要可用         | 存储层抽象接口（`PersistencePort`），IndexedDB 实现与 SQLite 实现并存，UI 不感知 |
| 文件名无规律导致的误识别 | 内容嗅探为主 + 低置信度进入人工确认界面，绝不静默错导                            |
| PDF 表格提取不稳         | P0 期不承诺 PDF；做「提取失败 → 引导提供同源 xlsx/csv」的兜底路径                |
| 备份文件损坏             | 所有备份带校验和 + schema 版本；恢复前 dry-run 校验                              |
| Tauri 学习成本           | M1 仅做壳，后端逐步增量；现有 `src/` 前端代码零改动迁移                          |
| 规则集兼容               | 计算引擎保持纯函数与现有单测覆盖，迁移只换存储不换逻辑                           |

## 附：与网页端的差异定位（摘要）

| 能力     | 网页端                           | 本地化后新增                                    |
| -------- | -------------------------------- | ----------------------------------------------- |
| 文件系统 | 文件选择器/下载                  | 目录扫描、监听、自动导入、备份直写、拖拽文件夹  |
| 解析     | xls/xlsx/csv                     | + PDF/HTML/TXT/OCR，表头智能映射、清洗管道      |
| 存储     | IndexedDB（GB 级配额、易被清理） | SQLite（10 万级记录、快照、加密、开放格式导出） |
| 计算     | 单规则集                         | 多规则集并行模拟、反推、敏感度                  |
